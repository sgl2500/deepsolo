```

        上 (远离屏幕)
       ↗
  左 ←   → 右
       ↘
        下 (靠近屏幕)

row 增大 → 屏幕右下
col 增大 → 屏幕左下
depth = col + row  (值越大越靠前/越靠近观察者)

玩家出生 (col=10, row=10) → depth=20
走到门口 (col=10, row=19) → depth=29
```

## 屋顶系统技术分析

### 渲染原理

building 层（屋顶）使用统一的 `roofOffset` 偏移到墙顶高度：

```
roofYoff = max(所有 surface 瓦片的 yoff)   // 取最大墙体高度 = 67
roofOffset = roofYoff - 20                 // 最终偏移 = 47
```

屋顶精灵位置: `sy - oy_roof - d4 - roofOffset`

### 为什么需要 -20px 额外偏移？

**这是菱形瓦片的几何特性导致的，不是 bug。**

核心原因：屋顶瓦片（如 622，36×22px）是**菱形**，而墙体瓦片（如 837，23×64px）是**矩形**。

```
菱形瓦片 622 (36×22):
    ▲          ← 顶部顶点 y=0, 宽度 ≈ 1px
   ╱ ╲
  ╱   ╲
 ╱     ╲      ← y≈11, 宽度 = 36px (最宽处)
  ╲   ╱
   ╲ ╱
    ▼          ← 底部顶点 y=21, 宽度 ≈ 1px

矩形墙体 837 (23×64):
 ┌──────┐      ← y=0, 宽度 = 23px
 │      │
 │ 墙体 │
 │      │
 └──────┘      ← y=63
```

**数学上正确的对齐（roofOffset = roofYoff = 67）：**
- 墙体可见顶部: sy - 67 - 4 = sy - 71
- 屋顶菱形底部顶点: sy - 21 - 4 - 67 + 21 = sy - 71
- 两者 Y 坐标完美对齐，但菱形底部顶点只有 **1 像素宽**，视觉上完全不可见

**实际需要的偏移（roofOffset = 47，即 -20px）：**
- 屋顶菱形下移 20px，使菱形的**宽体部分**覆盖墙体顶部
- 在墙体顶部位置，菱形宽度约 33px，形成清晰的视觉连接
- 20px ≈ 菱形底部顶点到最宽处的高度（半菱形高度）

### 经验教训

1. **菱形顶点是"虚"的**：等距菱形瓦片的四个顶点只有 1px 宽，不能作为视觉边界
2. **偏移量 ≠ yoff 对齐即可**：需要考虑瓦片的实际可见形状，而非仅看坐标
3. **地板层不存在此问题**：因为地板在 Canvas 上按画家算法渲染，相邻菱形自然重叠；但屋顶作为独立精灵，需要显式设置重叠量
4. **应先检查瓦片形状**：在计算偏移之前，应先查看瓦片图像是矩形还是菱形，菱形需要额外 half-height 的重叠

### 动态透明度

屋顶精灵根据玩家位置实时更新 alpha：

```typescript
updateRoofVisibility(playerCol, playerRow):
  REVEAL_RADIUS = 4   // 半径4格内渐变
  MIN_ALPHA = 0.15    // 中心最透明
  // 距离越远越不透明，超出半径完全实心
```

## 室内深度排序系统

### 核心发现：Phaser Container 不自动按 depth 排序

**这是最关键的渲染机制发现，任何室内场景都必须理解这一点。**

#### 问题描述

室内场景中，所有可见对象都放在 `indoorContainer`（Phaser Container）内：

```
indoorContainer
  ├── scrImage (Canvas 背景，depth=0)
  ├── 墙壁精灵 (depth = col+row 或 col+row+0.5)
  ├── 玩家容器 (depth = mapX+mapY)
  └── NPC 容器 (depth = mapX+mapY)
```

**Phaser 3 的 Container 默认按插入顺序渲染子对象，不会自动按 `depth` 属性排序。**

这意味着如果玩家容器在墙壁精灵之后添加到容器中，玩家会永远渲染在墙壁上面——无论 depth 值如何设置。这导致底部墙壁无法遮挡前方的玩家。

#### 添加顺序（SceneManager.ts onEnterMidpoint）

```
1. mapRenderer.switchToIndoor()     → 创建 indoorContainer，添加 Canvas + 墙壁精灵
2. mapRenderer.addIndoorChild(player) → 添加玩家容器（最后！）
3. mapRenderer.addIndoorChild(npc)    → 添加 NPC 容器（最后！）
```

不排序时，玩家和 NPC 始终渲染在所有墙壁上方。

#### 修复方案

在每帧的 `updateIndoorCamera()` 中调用 `container.sort('depth')`：

```typescript
// MapRenderer.ts — updateIndoorCamera()
this.indoorContainer.sort('depth');  // 关键！必须每帧排序
```

`sort('depth')` 按升序排列，depth 值小的先渲染（背景），大的后渲染（前景）。效果：

| 对象 | depth | 渲染顺序 |
|------|-------|----------|
| Canvas 背景 (scrImage) | 0 | 第1（最底） |
| 左上角墙壁 (0,0) | 0.0 | 第2 |
| 玩家在 (10,10) | 20.0 | ... |
| 底部墙壁 (1,19) | 20.5 | 在玩家之后（遮挡玩家） |
| NPC 在 (12,6) | 18.0 | ... |

#### depth 计算规则

```
Canvas 背景:      depth = 0
surface 精灵:     depth = col + row        (整数)
building 精灵:    depth = col + row + 0.5  (始终比同位置 surface 高 0.5)
玩家/NPC 容器:    depth = mapX + mapY      (浮点数)
```

关键：building 层 depth = col + row + 0.5，当玩家站在同一 (col, row) 位置时，玩家 depth = col + row < col + row + 0.5，所以 building 精灵总是渲染在玩家上方。

#### 经验教训

1. **永远不要假设 Container 会自动排序**：Phaser Container 的 `depth` 属性只影响全局渲染顺序（哪个容器在上面），不影响容器内部排序
2. **每帧必须调用 `sort('depth')`**：因为玩家/NPC 每帧移动都会改变 depth，需要重新排序
3. **添加顺序无关紧要**：有了 sort()，对象的添加/移除顺序不再影响渲染结果
4. **building 层的 +0.5 偏移**：确保同位置的遮挡物总是比玩家/NPC 的 depth 高 0.5，实现正确的遮挡关系

## 底部墙壁双层机制

### 为什么底部墙壁同时存在于 surface 和 building 两层？

底部墙壁（row 19）需要同时满足两个需求：

| 需求 | 由哪层实现 | 原因 |
|------|-----------|------|
| 碰撞检测 | surface 层 | `Player.isBlocked()` 检查 surface 层阻止玩家穿墙 |
| 渲染遮挡 | building 层 | depth = col+row+0.5 > 玩家 depth，墙壁渲染在玩家前面 |

### 渲染去重

当 surface 和 building 同位置有相同贴图 ID 时，只创建 building 精灵（不重复创建 surface 精灵）：

```typescript
// createWallSprites()
if (tileId !== 0 && !(bId !== 0 && tileId === bId)) {
  // surface 精灵：仅在 building 层没有相同贴图时创建
}
if (bId !== 0) {
  // building 精灵：始终创建
}
```

surface 层的贴图仍然会被渲染到 Canvas 上（`renderIndoorFloor()`），作为背景填充。building 精灵覆盖在 Canvas 上方，提供正确的深度排序。

### wall overlay vs roof 判定

building 层瓦片按 `yoff` 值分为两类：

| 类型 | 判定条件 | yOffset | 动态透明度 | 示例 |
|------|----------|---------|-----------|------|
| wall overlay | yoff > 30 | 0（不偏移） | 不参与 | 底部墙壁 (yoff=67) |
| roof | yoff ≤ 30 | roofOffset | 参与 | 屋顶 622 (yoff=21) |
