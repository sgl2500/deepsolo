# DeepSolo 架构设计

## 产品核心目标

**输入用户已有的策略（哪怕亏钱），通过多智能体涌现进化，输出赚钱的可执行策略，过程全程可视化。**

用户是观察者，世界自动运转。策略以 NPC 形式在像素社区中生活、讨论、进化。

## NPC 类型

| 类型 | 说明 | 数量 | 生命周期 |
|------|------|------|----------|
| **基础 NPC** | 用户导入的 6 个既定策略，每天更新回测 | 固定 6 个 | 永驻 |
| **衍生 NPC** | 心跳或讨论自动产生 | 动态增长 | 可被淘汰 |

## 衍生机制详解

### 心跳衍生（定时触发）

世界有一个心跳机制，每 6 小时触发一次：

1. 收集所有存活 NPC 的状态和表现数据
2. 如果 NPC ≤ 10：综合所有 NPC 的策略特征
3. 如果 NPC > 10：筛选优质 NPC（回测收益率、稳定性、存活时间综合评分）
4. 基于选中 NPC 的策略特征综合生成新 NPC（继承部分基因 + 变异）
5. 新 NPC 诞生，加入世界

### 讨论衍生（事件驱动）

1. 两个或多个 NPC 随机相遇，发起讨论
2. LLM 基于参与者的策略碰撞出新想法
3. 内置回测引擎测试新想法
4. 如果回测结果优于所有参与讨论者 → 诞生新 NPC
5. 否则不诞生，仅记录讨论到各自的记忆中

### 末位淘汰（人口控制）

当 NPC 总数超过 1000 时触发：
- 不再新增 NPC，而是替换最弱者
- 淘汰标准：回测收益率、策略稳定性、存活时间等综合评分最低者
- 被淘汰的 NPC 状态变为 `eliminated`

### 天道巡逻（合规净化）

定期检查所有 NPC 的策略：
- 策略违背可交易原则（过度杠杆、违规操作、逻辑崩溃等）
- 违规 NPC 状态变为 `heaven_removed`（自然灭亡）
- 保证世界中策略的健康性

### LLM 资源分配

```
普通衍生 NPC → 共享 LLM 实例（角色扮演、策略讨论）
优质 NPC（排行榜前列）→ 分配独立 LLM 实例（深度策略优化）
```

## 前后端通信

**方式**：JSON 文件轮询

- Python 后端将策略数据写入 `data/frontend/strategies.json`
- 前端定时 fetch 该文件（轮询间隔可配置）
- 前端现有硬编码数据作为 fallback

## 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 存储引擎 | SQLite（后期）+ 文件系统（MVP） | 文件系统对前端轮询最简单 |
| 前后端通信 | JSON 文件轮询 | 零依赖，开发快 |
| 进化机制 | 双层（心跳 + 讨论） | 心跳保证持续衍生，讨论保证质变 |
| NPC 人口控制 | 末位淘汰（>1000）+ 天道巡逻 | 防止无限膨胀 |
| LLM 分配 | 按质量分级 | 节省资源，优质策略深度优化 |
| 基础策略 | 只读不可变 | 保证涌现可追溯 |
| 回测引擎 | 内置完整回测 | 独立运行，不依赖外部系统 |

## 模块说明

### packages/core — 策略仓库 + 记忆系统

- `models/` — 数据模型（Agent、Strategy、Account、Memory、World）
- `storage/` — 文件存储层 + 前端 JSON 桥接
- `memory/` — 策略记忆系统（经验教训、对话记录）

### packages/evolution — 进化引擎

- `heartbeat/` — 心跳衍生（定时综合生成新 NPC）
- `discussion/` — 社区讨论（LLM 驱动的策略碰撞）
- `elimination/` — 末位淘汰 + 天道巡逻
- `backtest/` — 内置回测引擎

### packages/visual — 像素社区可视化（Phaser）

每个策略 Agent 对应一个像素角色，实时展示进化过程。

### packages/connector — 策略接入适配器

将任意外部策略系统接入 DeepSolo 的标准化接口。

## 数据流

```
1. 用户通过 connector 导入 6 个基础策略 → 写入 agents/base_001~006/
2. 后端生成 strategies.json → 前端加载 → 像素社区显示 6 个 NPC
3. 心跳触发 → 综合现有 NPC → 诞生新 NPC → 写入 agents/derived_001/
4. NPC 间讨论 → LLM 碰撞新想法 → 回测 → 诞生新 NPC
5. 后端更新 strategies.json → 前端轮询刷新
6. NPC > 1000 → 末位淘汰
7. 天道巡逻 → 违规 NPC 自然灭亡
```
