# DeepSolo 架构设计

## 产品核心目标

**输入用户已有的策略（哪怕亏钱），通过多智能体涌现进化，输出赚钱的可执行策略，过程全程可视化。**

所有设计围绕这一个目标。

## 模块说明

### packages/core — 策略仓库 + 记忆系统

策略的存储、记忆、关系管理。

- `models/` — 策略数据模型（基础策略、涌现策略、关系）
- `storage/` — SQLite 存储层（CRUD、查询）
- `memory/` — 策略记忆系统（表现快照、决策日志、经验教训、进化轨迹）

### packages/evolution — 进化引擎

双层涌现机制。

- `competition/` — 第一层：生态竞争（参数变异、规则杂交、排行榜淘汰）
- `community/` — 第二层：社区协作（LLM 驱动的策略讨论、新思路提取）

### packages/visual — 像素社区可视化

每个策略 Agent 对应一个像素角色，实时展示进化过程。

### packages/connector — 策略接入适配器

将任意外部策略系统（OpenClaw / 自研）接入 DeepSolo 的标准化接口。

## 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 存储引擎 | SQLite（初期） | 轻量、零配置、本地优先 |
| 进化机制 | 双层（竞争 + 协作） | 量化进化保证规模，LLM协作保证质变 |
| 策略接入 | 标准化数据结构 | 与用户策略系统解耦 |
| 基础策略 | 只读不可变 | 保证涌现可追溯 |
| 涌现产出 | 可执行文件 | 不是思路，是直接可运行的策略代码 |

## 数据流

```
1. 用户通过 connector 上传策略数据 → 写入基础策略层（只读）
2. 进化引擎读取基础策略 → 生态竞争产生参数变异/杂交 → 写入涌现策略层
3. 优秀涌现策略进入社区讨论 → LLM 提取新规则 → 写入涌现策略层
4. 所有策略关系写入关系记忆层
5. 涌现策略的可执行文件通过 connector 回传给用户
6. 用户本地执行 → 新的表现数据 → 下一轮进化
```
