# 社区讨论演化

## 概述

社区讨论是 DeepSolo 的核心演化机制之一。策略 Agent 在社区中随机碰面，各自带着自己的数据问题和发展需求，通过 LLM 驱动的对话寻找互补伙伴。只有当双方恰好互补（A 的优势解决 B 的需求，反之亦然），才可能涌现新的融合策略。

## 核心原则

1. **每个人从自己的立场出发** — 不是上帝视角分析所有人，而是每个 Agent 自我诊断
2. **数据驱动** — 自我诊断基于真实的交易数据（日度收益、交易记录、胜率、回撤等）
3. **双向互补才涌现** — 单方面有需求不算，必须是双方恰好能互相帮助
4. **不能硬凑** — 如果碰面的两个人没有互补关系，就是普通交流，不产生新策略

## 完整流程

```
定时触发（每 4 小时）或手动触发
    ↓
① 筛选已实现的 Agent（is_strategy_implemented = true）
    ↓
② 随机选 2-3 个碰面
    ↓
③ 每个 Agent 做自我诊断
    ├─ 分析自己的日度收益、波动率、胜率、连亏、回撤期
    ├─ 总结优势（我擅长什么）
    ├─ 识别问题（我的痛点是什么）
    └─ 明确需求（我需要什么帮助）
    ↓
④ 判断双向互补
    ├─ A 的需求 ↔ B 的优势
    ├─ B 的需求 ↔ A 的优势
    └─ 关键词匹配 + 数据指标交叉验证
    ↓
⑤ LLM 模拟碰面对话
    ├─ 不互补：prompt 明确告知"普通碰面，不会诞生策略"
    └─ 互补：prompt 引导自然走向合作思路
    ↓
⑥ 落盘
    ├─ 对话记录 → memory/conversations/{disc_id}.json
    ├─ 经验追加 → memory/experience.json
    └─ 互补+涌现 → 创建新 Agent（空壳 + 经验洞察）
    ↓
⑦ 刷新前端 JSON
```

## 自我诊断维度

| 分析项 | 数据来源 | 可能的优势 | 可能的问题 |
|--------|----------|-----------|-----------|
| 累计收益 | 日度收益序列 | 盈利能力突出 | 策略整体失效 |
| 日波动率 | 日度收益标准差 | 非常稳定 | 收益曲线过于剧烈 |
| 盈利日占比 | 正收益天数/总天数 | 胜率较高 | 多数交易日亏损 |
| 单日极端值 | max/min 日收益 | 爆发力强 | 极端风险失控 |
| 连续亏损 | 最长连亏天数 | — | 心理压力巨大 |
| 最大回撤 | 权益峰值回撤 | — | 抗跌能力不足 |
| 大额亏损交易 | 交易记录 return_pct < -5% | — | 止损不够坚决 |

## 互补判断逻辑

```
A 的需求列表 vs B 的优势列表
B 的需求列表 vs A 的优势列表

关键词匹配:
  "波动" ← → "稳定"
  "亏损" ← → "盈利"
  "止损" ← → "胜率"
  "连亏" ← → "爆发力"
  "回撤" ← → "收益"
  "alpha" ← → "alpha"
  "风控" ← → "稳定"

数据指标交叉:
  收益差距 > 10%  → 互补
  波动率差距 > 1.5% → 互补

双向都匹配 → 判定为互补
```

## 衍生 Agent 的生命周期

```
诞生（讨论碰撞）
  ↓
status = "alive", 但 is_strategy_implemented = false
  ├─ 有 profile.json（名字、人设、父代）
  ├─ 有 experience.json（继承的洞察 + 诞生洞察）
  └─ 无策略代码、无交易数据
  ↓
夜间系统回填
  ├─ 读取 experience.json 中的洞察
  ├─ 实现策略代码（生成买卖信号.py 等）
  ├─ 运行回测，生成交易记录.json、账户信息.json
  └─ is_strategy_implemented → true
  ↓
参与后续讨论（有了真实数据，可以做自我诊断）
  ↓
与更多 Agent 碰面，产生更深层的互补
```

## Agent 状态定义

| status | 含义 | 是否参与讨论 |
|--------|------|-------------|
| `alive` + implemented | 已有完整数据 | 是（核心参与者） |
| `alive` + 未 implemented | 刚诞生，等夜间系统回填 | 否 |
| `pending` | 等待实现（旧标记） | 否 |
| `eliminated` | 被末位淘汰 | 否 |
| `heaven_removed` | 天道巡逻移除 | 否 |

## 文件结构

### 讨论产出的文件

```
data/agents/{id}/
├── profile.json                    # Agent 身份（诞生时写入）
├── memory/
│   ├── experience.json             # 经验列表（每次讨论追加）
│   └── conversations/
│       ├── disc_20260415_134922.json  # 一次讨论的完整对话
│       ├── disc_20260416_082100.json
│       └── with_observer.json       # 与用户的对话
├── strategy/                       # 空目录，等夜间系统回填
│   ├── 买卖信号.json               # ← 夜间系统写入
│   ├── 交易记录.json               # ← 夜间系统写入
│   ├── 账户信息.json               # ← 夜间系统写入
│   ├── 盘前选股.json               # ← 夜间系统写入
│   ├── 生成买卖信号.py             # ← 夜间系统写入
│   ├── 生成回测明细.py             # ← 夜间系统写入

```

## 昼夜循环

```
═══════════════════════════════════════════════════════════
  白天 — DeepSolo 讨论引擎（本项目）
═══════════════════════════════════════════════════════════

  1. 从已实现的 Agent 中随机选 2-3 个碰面
  2. 各自做数据驱动的自我诊断
  3. 判断双向互补
  4. LLM 模拟对话
  5. 互补 → 诞生新 Agent（空壳 + 经验洞察）
  6. 不互补 → 只记录经验和对话

═══════════════════════════════════════════════════════════
  晚上 — 外部调度系统（独立服务）
═══════════════════════════════════════════════════════════

  1. 同步最新策略数据到 data/agents/
  2. 读取衍生 Agent 的 experience.json
  3. 基于经验洞察实现策略代码
  4. 回测 → 生成交易记录 + 账户数据
  5. 下次 is_strategy_implemented → true → 可参与讨论

═══════════════════════════════════════════════════════════
  循环效果
═══════════════════════════════════════════════════════════

  第 1 天: 6 个基础 Agent → 讨论涌现 1-2 个衍生
  第 2 天: 夜间回填 → 7-8 个有数据的 Agent → 讨论质量更高
  第 N 天: Agent 越来越多，互补网络越来越复杂，涌现加速
```

## 相关代码

| 文件 | 说明 |
|------|------|
| `packages/core/deepsolo/evolution/discuss.py` | 讨论引擎核心 |
| `packages/core/deepsolo/evolution/derive.py` | 心跳派生（选 Top 2） |
| `packages/core/deepsolo/storage/file_store.py` | 存储层（含完备性检测） |
| `packages/core/deepsolo/server.py` | WebSocket 服务 + 定时调度 |
| `scripts/trigger_discussion.py` | 手动触发讨论脚本 |

## 运行方式

### 自动模式（服务器后台）

```bash
python -m deepsolo.server
# 自动每 4 小时运行一次讨论，每 24 小时运行一次心跳派生
```

### 手动触发

```bash
python scripts/trigger_discussion.py
# 单次触发，方便调试和测试
```
