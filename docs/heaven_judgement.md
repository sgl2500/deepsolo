# 天道惩罚系统

## 概述

天道惩罚系统是独立于 Agent 之外的审查系统，每天扫描所有具有实际回测数据的衍生 Agent，检测未来函数和逻辑不自洽。发现违规者直接人道消灭，并生成天罚报告。

**基础 Agent（hv1-hv4, nv1-nv2）不受天罚约束。**

## 设计原则

1. **只审衍生 Agent** — 基础 Agent 是用户原始策略，是世界的基石，不可惩罚
2. **只审有数据的** — 没有回测数据的空壳 Agent 无从审起
3. **独立运行** — 天罚系统不参与讨论、不参与演化，只做审查
4. **消灭 + 报告** — 发现问题不给警告机会，直接消灭，附详细审查报告

## 审查维度

### 一、未来函数检测

未来函数是量化回测中最致命的问题——策略在回测中使用了实际交易时不可能获得的信息。

| 违规类型 | 说明 | 检测方法 |
|---------|------|---------|
| 用当日收盘价决策 | 买入信号依赖当日收盘价，但实际交易时收盘价未知 | 检查买入时间和所用数据的时间关系 |
| 用次日最高价卖出 | 卖出用了次日最高价，实际无法预知 | 检查卖出价格是否为当日最高价（不可能精准卖在最高） |
| 用全局排名信号 | "涨幅前5"需要全市场数据，且需要收盘后才能排序 | 检查 `盘前选股.json` 和 `买卖信号.json` 的买入原因 |
| 用未来数据计算指标 | 比如用未来 20 日均线做买入判断 | 检查策略代码中是否有 look-ahead |
| 卖在最高/最低价 | 精准卖在极值点，现实中不可能 | 检查卖出价格与当日最高/最低价的关系 |

### 二、逻辑自洽检测

策略的实际行为与其声称的逻辑是否一致。

| 违规类型 | 说明 | 检测方法 |
|---------|------|---------|
| 持仓天数矛盾 | 描述说"次日卖出"，实际持有 3-5 天 | 检查 `交易记录.json` 中 hold_days 分布 |
| 仓位矛盾 | 描述说"单票不超 20%"，实际有单票 50% | 检查每笔交易的 cost 占总资金比 |
| 策略描述与信号不符 | 描述说"竞价选股"，信号里有盘中追涨 | 检查 buy_time 和 buy_reason |
| 回测收益与明细对不上 | 账户显示 +30%，但交易明细加起来不是 | 用交易记录重算总收益 |
| 胜率异常 | 胜率 > 80% 且交易次数 > 50，极可能是过拟合或作弊 | 统计胜率 + 交易次数 |
| 单笔极端收益 | 单笔收益 > 30%，极不正常 | 检查 return_pct 分布 |

## 审查流程

```
每天定时触发
    ↓
① 筛选审查对象
    ├─ type = "derived"（排除基础 Agent）
    └─ is_strategy_implemented = true（排除空壳）
    ↓
② 读取 Agent 完整数据
    ├─ profile.json（策略描述、关系）
    ├─ 生成买卖信号.py（策略代码）
    ├─ 买卖信号.json（信号记录）
    ├─ 交易记录.json（逐笔交易）
    └─ 账户信息.json（汇总 + daily 序列）
    ↓
③ LLM 审查
    ├─ 输入：策略描述 + 代码 + 交易数据（采样）
    ├─ 要求 LLM 从 6 个维度逐一审查
    ├─ 每个维度给出结论：通过 / 违规 + 证据
    └─ 综合判定：清白 / 有罪
    ↓
④ 判定结果
    ├─ 清白 → 什么都不做
    └─ 有罪 → 人道消灭 + 天罚报告
```

```python
  "agent_name": "[杂交]动态HV混合",
  "verdict": "guilty",
  "timestamp": "2026-04-16T08:00:00Z",
  "violations": [
    {
      "type": "future_function",
      "severity": "critical",
      "description": "卖出逻辑使用了次日最高价作为卖出价格",
      "evidence": "交易 #45 20260215 卖出价 18.92 等于当日最高价，命中 3 次以上"
    },
    {
      "type": "logic_inconsistency",
      "severity": "warning",
      "description": "策略描述声称'次日开盘卖出'，实际平均持仓 2.3 天",
      "evidence": "hold_days 分布: 1天=40%, 2天=35%, 3天=25%"
    }
  ]
}
```

## 前端表现

- 被 `heaven_removed` 的 NPC 从策略列表中消失（status 过滤）
- 可在"天道日志"面板中查看历史惩罚记录
- Agent 被消灭时可以播放一个特效（闪电/雷击）

### LLM Prompt 结构

```
你是一个量化策略审查员。请审查以下策略是否存在未来函数或逻辑不自洽。

## 策略信息
名称: xxx
描述: xxx

## 策略代码
{生成买卖信号.py 的内容}

## 交易记录（最近 20 笔采样）
{交易记录.json 的部分内容}

## 账户汇总
{账户信息.json 的 summary}

## 日度数据（最近 10 天）
{daily 的部分内容}

## 审查清单
1. 未来函数：策略代码是否使用了实际交易时不可得的信息？
2. 卖出价格异常：是否精准卖在最高/最低价？
3. 持仓天数矛盾：实际持仓与策略描述是否一致？
4. 仓位矛盾：实际仓位与策略描述是否一致？
5. 收益数据一致性：交易明细之和是否等于账户汇总？
6. 异常收益：是否存在不正常的极端单笔收益？

## 输出格式
JSON:
{
  "verdict": "innocent" 或 "guilty",
  "violations": [
    {"type": "...", "severity": "critical/warning", "description": "...", "evidence": "..."}
  ]
}
```

## 调度

- **触发时间**：每天一次（建议凌晨，在夜间系统回填数据之后）
- **与讨论引擎的关系**：天罚在讨论之前运行，确保参与讨论的 Agent 都是"清白"的
- **执行顺序**：天罚审查 → 淘汰违规者 → 社区讨论（只选清白 Agent）

## 数据流

```
夜间系统回填数据
    ↓
天罚审查（每天一次）
    ├─ 读取衍生 Agent 的策略代码 + 交易数据
    ├─ LLM 逐维度审查
    ├─ 有罪 → heaven_removed + 天罚报告
    └─ 清白 → 无事发生
    ↓
社区讨论（只选清白的 implemented Agent）
```
